# AI生成LPをAIっぽくしないための改修ガイド

作成日: 2026-05-29
目的: AIで生成したLPを他LPサイトへ横展開する際に、AIっぽさを取り除くための改修ポイントをまとめたメモ。
このメモをAIに読ませることで、AI生成LPの改修指示として活用できる。

## はじめに

AIで生成したLPは完成度が高く、従来と比べて短時間で構築できるのが魅力。
ただし指定しない限り「AIが生成した感じ」が残る。
他のLPサイトを横展開するときに、同じパターンに陥らないようにするための改修ポイントをまとめた。

## AI生成LPによくあるパターン

- ①②③から始まる箇条書き
- 重複した説明
- 遷移しないのに浮き上がってくるセクション
- とにかくカードグリッド
- とにかくグラデーション
- とにかくドロップシャドウ

## 改修ポイント

「全体に関わるもの → ページ上から下」の順に並べた。

### 1. フォントをクラスメソッドのコーポレートサイトに揃える

- 症状: 欧文フォントがGoogle Fontsから自動で選ばれる
- 改修: classmethod.jpで使われているAdobe Fontsの univia-pro を `<link>` で読み込み、`--font-sans` の先頭に追加する

### 2. リンク色をクラスメソッドのコーポレートサイトに揃える

- 症状: 指定しない限りリンクに必要なコントラスト比や下線（色だけに頼らずリンクと分かる視覚的な区別）が適用されず、全体のトーンに合う色が選ばれがち
- 改修: classmethod.jpのリンク色 `#2D8DE0` を取り込み、`--link` / `--link-hover` トークンを新設する
- 該当ガイドライン: [WCAG 1.4.1 色の使用](https://waic.jp/translations/WCAG22/#use-of-color) と [WCAG 1.4.3 コントラスト（最低限）](https://waic.jp/translations/WCAG22/#contrast-minimum)

### 3. テキストと背景のコントラスト比をWCAG AA基準で確認する

- 症状: 緑系（`#06C755` など）のリンク色や強調文字が白背景に対して2.4:1〜3.3:1とAA基準（4.5:1）に未達なことがある
- 改修: コントラスト比がAA基準を満たすよう色を再選定する（リンクはclassmethod.jp青系、価格表示は黒系など）

### 4. デザイントークンの散在を整える

- 症状: 定義済みデザイントークンがあるのにhex直書き（例: `text-[#4B5563]`）で迂回している
- 改修: hex直書きを `muted-foreground` などの既定トークンに置き換える

### 5. 画像の sizes 属性を指定する

- 症状: Next.jsの `<Image fill />` で `sizes` 未指定で、実表示サイズに対して過大な画像が配信される（例: 表示44x44pxなのに100vw想定で配信）
- 改修: `sizes="44px"` のように実表示サイズに合わせて指定する

### 6. ヘッダー/フッターをスマホ向けに再設計する

- 症状: デスクトップ前提のレイアウトになりがちで、スマホサイズで横並びヘッダーや多段リンクフッターが破綻する
- 改修: ハンバーガー化・縦並びレイアウトに再設計する（全ページ共通のHeader/Footerコンポーネントで対応）

### 7. ベース背景をクラスメソッドのコーポレートサイトに揃える

- 症状: ヒーローや特定セクションが濃い黒（`#0a0a0a` / `#0d0d0d` など）になり、コーポレートサイトとトーンがずれる
- 改修: classmethod.jpと同じ `#f5f5f5` のライトグレーに統一する。連動して白テキスト→foreground、緑テキスト→line-green-dark、装飾の緑グローも整理する

### 8. ロゴ・アイコンを差し替える

- 症状: ロゴやアイコンは指定しないと「G」マークのような汎用プレースホルダで埋まる
- 改修: 使ってほしいロゴやサービス名に差し替える

### 9. 記号から適切なアイコンに差し替える

- 症状: 文頭に「・」など記号や絵文字を並べる形になりやすい（例: 「・LINEヤフー Partner Program Technology Partner」）
- 改修: 認定や受賞バッジは Award アイコン+テキストの形に変更する（AWS Premier Tier Services Partnerで使われている表現が参考になる）

### 10. テンプレ的なカードグリッドの取り扱い

- 症状: 同一テンプレで10連発のカードグリッド（Identical card grid）が採用される。Impeccableでは「絶対バン」扱いで検出される
- 改修判断: LPで全機能を一覧で見せる目的がある場合、構造を崩すと設計意図が失われるためそのまま残す判断もある。アンチパターン検出は機械的に動くので、目的に応じて採用/不採用を判断する

### 11. 巨大数字カード（hero metric）のレイアウト調整

- 症状: 巨大な数字カードが採用される場合、カード幅と内部要素の関係まで整っておらず、数値が途中で改行されることがある（例: 「5,000」が途中で改行）
- 改修: カードの最小幅を指定して数値を1行に収める。または「巨大数字+サブ統計」のエディトリアルレイアウトに作り直す

### 12. 不要なドロップシャドウを削除する

- 症状: 装飾としてドロップシャドウや枠が多くの項目に入る
- 改修: 目立たせる必要のない項目からドロップシャドウを削除する

### 13. 冗長なステップバッジを削除する

- 症状: ①の隣に「Step 1: 〇〇」と並んで冗長な表現になっていることがある。Impeccableも部分的に指摘するが、全体を見渡して統一する判断は人間が必要
- 改修: 冗長な表現は削除して、片方に統一する

### 14. カテゴリラベルの位置とサイズを上げる

- 症状: カテゴリやステップなどの分類ラベルが、見出しや本文より小さく目立たない位置に置かれる
- 改修: ラベルをカード左上に移動し、フォントサイズを2段階上げて視認性を上げる

### 15. マウスを乗せたときのフィードバックを追加する

- 症状: 静的な見た目は整っていても、マウスを乗せたときのインタラクションまでは差別化されない
- 改修: 遷移先があるものとないもので変化をつける（緑ボーダーhover + focus-visibleリングなど）。focusは `focus:` ではなく `focus-visible:` を使ってキーボード操作時のみ表示する

### 16. SaaS比較カードの強調表現を整理する

- 症状: 「RECOMMENDED」プランなどに、ドロップシャドウ・緑の枠線・緑のラベルと、強調が3つ重なる
- 改修: 枠線だけで十分目立つので、ドロップシャドウは削除する

### 17. 営業コピーを視覚的に目立たせる

- 症状: コピーは生成されていても、営業上の訴求ポイントを視覚的に立たせる判断までは入っていない
- 改修: 訴求したいコピー（例: 「初回相談は無料です。」）を太字にして視線が止まるようにする

## ブランド統一チェックリスト

横展開時に揃えるべき値。

| 項目       | 値                                            |
| ---------- | --------------------------------------------- |
| フォント   | univia-pro（Adobe Fonts）+ Noto Sans JP       |
| リンク色   | `#2D8DE0`                                     |
| ベース背景 | `#f5f5f5`（classmethod.jpと同じライトグレー） |
| 認定バッジ | ドット記号ではなくアイコン+テキスト           |
| focus      | `focus-visible:` でキーボード操作時のみ表示   |

## 補助ツール: Impeccable

Claude Codeに追加できるSkill。手作業で全部見る前に走らせると、機械的に拾える問題を粗削りできる。

| コマンド             | 内容                                                                                                              | 検証時間 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- | -------- |
| `/impeccable audit`  | コードを変更せず、5観点（Accessibility / Performance / Responsive / Theming / Anti-Patterns）でスコアと指摘を返す | 約3分    |
| `/impeccable polish` | 仕上げ修正（コントラスト・装飾アンチパターン削除・sizes属性追加・prefers-reduced-motion対応など）                 | 約20分   |
| `/impeccable bolder` | 地味なデザインを強める修正（タイポ階層・hero-metricテンプレ解体など）                                             | 約7分    |

機械的に拾えるのは「数値で測れる問題（コントラスト・画像配信サイズ・トークン整合性）」と「装飾アンチパターン」まで。
「ブランド統一」「固有名詞」「情報整理」「強調表現の意図」は拾えないので、上記の改修ポイントで人間判断が必要。
